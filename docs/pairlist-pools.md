# Pair-List Pools (`docs/pairlist-pools/`)

Committed, hash-locked synthetic-pair universes for S&P-500 TOP_MEAN campaigns. Each pool is a `<name>.json` registry (schema `pool-registry.v1`) plus a `<name>.txt` pair list (one `BASE+QUOTE` line per pair; IBKR legs carry the `•` marker from `markIbkrSymbol` in `lib/local-daily-datasets.ts`). These files are load-bearing data, not examples — a regression test fails if they drift.

| `BAL5555-S2.v1` | 136 IBKR-marked (`AAPL•`) | 5555 | 2 | pair legs of the L1 campaign manifest `sp500_top_mean_1788443592188_cgd3` |

All pools are generated by `generateBalancedPairList` (`lib/batch-backtest/balanced-pair-list-generator.ts`, algorithm `seeded_round_robin_v1`), which guarantees:

- deterministic regeneration from the asset list + seed,
- balanced asset degree (max degree − min degree ≤ 1),
- orientation imbalance ≤ 1,
- a `pairListSha256` pinning the exact pair-list content.

`BAL5555-S2.v1` stores marked tokens deliberately: unmarked USDT-derived legs (e.g. `KHCUSDT`) route to Binance, which is wrong for this data surface — see the v1.1 note in `scripts/generate-bal5555-pairlist.ts`.

## Who reads them

- **Archive manifests**: `findRegistryPoolMatch` (`lib/batch-backtest/sp500-top-mean-archive-log.ts`) matches a finished TOP_MEAN run's pair set against every registry — same pair count, same normalized asset-pair set (IBKR markers ignored), same `pairListSha256`. A unique match stamps `poolVersion`, `algorithm`, and `seed` into the archive manifest, so archived campaigns record which pool they ran. Zero or multiple matches record no pool.
- **Integrity test**: `tests/pairlist-pool-registry.spec.ts` locks schema, counts, degree balance, and hashes of the committed files. Any edit to a registry in place fails the test — that is intentional.

## Regenerating / adding a pool

- `scripts/generate-bal679-registry.ts` and `scripts/generate-bal5555-pairlist.ts` are assert-heavy one-shot generators (run with `npx esno scripts/<name>.ts`; they are not npm scripts). Each reads its source assets from `archive/batch-open-score/<run>/meta.json`, regenerates the pool, and writes the registry + txt to `docs/pairlist-pools/` (committed) and `archive/batch-open-score/pools/` (local research copy).
- To add a new pool, follow the same pattern: bump `poolVersion`, never mutate an existing registry (its hash is pinned by the spec and by already-written archive manifests).

Token forms differ between pools (canonical vs marked). Consumers normalize through `normalizeAssetPairSet` / `canonicalizeLegIdentity` — never compare raw leg strings across pools.
