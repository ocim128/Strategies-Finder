# Plan: Remove Snapshot Entry Filters + Snapshot Capture System

## Goal

Remove the entire snapshot entry filter system (22 toggle/min/max settings that gate trade entries) AND the snapshot capture system (TradeSnapshot data captured per-trade for post-analysis). This includes the `captureSnapshots` setting, all downstream analysis, UI, and type infrastructure.

## Scope Summary

~30+ files touched, ~3000+ lines removed, several files deleted entirely.

**Keep:** `snapshot-derived-metrics.ts` (renamed to e.g. `bar-metrics.ts`) because `adaptive-take-profit.ts` depends on its general-purpose metric computation helpers.

## Execution Order

Recommended order to minimize broken intermediate states:

1. Phase 1 (execution path) — backtests immediately work without filters
2. Phase 2 (capture infra) — backtests stop producing snapshots
3. Phase 3 (types + consumers) — clean up all downstream code
4. Phase 4 (settings infra) — clean settings pipeline
5. Phase 5 (HTML) — clean UI
6. Phase 6 (callers) — clean `captureSnapshots` options
7. Phase 7 (tests) — fix/rewrite tests
8. Phase 8 (docs) — update documentation
9. Phase 9 (barrels) — clean exports

Run `npm run typecheck` after each phase to catch cascading type errors.

## Risk Areas

- **`adaptive-take-profit.ts`** imports from `snapshot-derived-metrics.ts` — must keep the file (renamed) and its needed exports
- **`trade-analyzer.ts`** is deeply intertwined with `TradeSnapshot` — removing it may cascade into finder robustness scoring; check if Finder uses feature ranges from trade-analyzer
- **Polymarket panel** uses snapshot profiles for suggestions — this feature will be lost
- **localStorage migration** — existing persisted settings may contain snapshot keys; the read path should silently ignore unknown keys (already handled by resolver's whitelist), but verify
- **Worker compatibility** — `captureSnapshots` was already unsupported by Rust; removing it simplifies rather than complicates the Rust sanitization path
