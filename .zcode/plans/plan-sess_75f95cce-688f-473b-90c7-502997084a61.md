## Post-Run Re-Sort for All Finder Scopes

### Goal
After a Finder run completes, the user can change the sort metric from a dropdown and the top-N results re-order instantly — no re-run needed. Applies to all three scopes: current_chart, symbol_universe, and asset_opportunity.

### Performance impact
**Zero.** Re-sorting calls the existing pure in-memory comparators (`sortFinderResults`, `sortFinderUniverseCandidates`, or a new parameterized asset comparator) on ≤25 retained results. O(25 log 25) = microseconds.

### Design decisions
- **Default = "Run Sort"** (the original run-time sort). Selecting any metric switches to pure metric sort. This preserves the proven default and explicitly opts the user into overriding it.
- **One unified re-sort dropdown** in the results area, visible for all scopes after a run. Scope-specific options.
- **Existing pre-run sort dropdowns stay unchanged** — they set the sort for the *next* run. The new dropdown only affects the *current* result list display.

### Constraint to document
Re-sorting only re-orders the already-retained top-N survivors. Candidates that ranked outside top-N under the original run sort are not recoverable.

---

### Implementation (7 steps)

#### 1. Add re-sort HTML (tab-finder.html)
Add a re-sort dropdown in the `.finder-actions-bar` (line 342), next to the existing Copy buttons:

```html
<div class="finder-resort-group">
    <label class="param-label" for="finderResort">Re-Sort</label>
    <select class="param-input" id="finderResort">
        <option value="">Run Sort (default)</option>
    </select>
</div>
```

#### 2. Register DOM contract (finder-manager-dom.ts)
Add `"finderResort"` to `FINDER_MANAGER_REQUIRED_IDS` and `createFinderManagerDom()`.

#### 3. Parameterize the Asset Opportunity comparator (finder-asset-opportunity-metrics.ts)
Add a new function `sortAssetOpportunityResultsByMetric(results, metric)` that sorts by a single `FinderMetric` reading from `selectionResult`. Keep the existing `sortAssetOpportunityResults(results)` unchanged for the run path. The new function:
- When `metric` is null/undefined → falls back to the existing grade-first comparator
- When `metric` is set → pure descending sort by that metric on `selectionResult` (ascending for maxDrawdownPercent), with `symbol` as the tie-breaker

#### 4. Populate re-sort options per scope (finder-manager.ts)
New method `populateResortOptions()` called on:
- Scope change (`applyScopeUi`)
- Run completion (before `renderLatestResults`)

Options per scope:
- **current_chart**: `FINDER_SORT_OPTIONS` (the same 12 metrics the pre-run sort offers)
- **symbol_universe**: `UNIVERSE_SORT_OPTIONS` 
- **asset_opportunity**: a curated subset of `FINDER_SORT_OPTIONS` that maps to `selectionResult` scalars (netProfit, profitFactor, sharpeRatio, winRate, maxDrawdownPercent, expectancy, totalTrades, averageGain, netProfitPercent)

All use `METRIC_FULL_LABELS` for display text.

#### 5. Re-sort handler (finder-manager.ts)
Add a `change` listener on `#finderResort` that:
1. Reads the selected metric from the dropdown
2. Branches on `latestResults.scope`:
   - `current_chart`: `sortFinderResults(results, [metric])` (existing pure sort)
   - `symbol_universe`: `sortFinderUniverseCandidates(results, [metric])` (existing pure sort)
   - `asset_opportunity`: `sortAssetOpportunityResultsByMetric(results, metric)` (new function from step 3)
3. `setLatestResults({ scope, results: sorted })` + `renderLatestResults()`

When metric is empty (default "Run Sort"), restore the original run-time ordering. To support this, stash the original results before any re-sort (a `originalLatestResults` field set on run completion).

#### 6. Reset re-sort dropdown on new run
At the start of `runFinder()` and on `onAssetDone`/`onResultsDone`, reset `#finderResort` to the default empty option and clear the `originalLatestResults` stash.

#### 7. Update feature-dom-contracts spec
The new `finderResort` ID is auto-verified by the existing `feature-dom-contracts.spec.ts` (which checks every ID in `FINDER_MANAGER_REQUIRED_IDS` exists in the HTML partial).
