## Plan — Two risk-management features

### Feature 1: Configurable entry cooldown (post-exit bars)

A new Risk Management setting `riskCooldownBars` (with toggle `riskCooldownEnabled`) that blocks new entries for N bars after ANY trade closes. Replaces the hardcoded `SIGNAL_EXIT_REENTRY_COOLDOWN_BARS = 1` with the configurable value (default 1 preserves current behavior). All exits fire it (signal, SL, TP, path-exit, time-stop, max-hold, EOD), both directions, in all 4 engine loop paths.

**Follows the `riskMinHoldBars`/`riskMaxHoldBars` analog exactly.**

### Feature 2: Randomize Path Exits works under freeze

Currently `freezeRiskManagement=true` forces `randomizePathExitParams=false` and the 3 finder-core functions short-circuit on freeze, skipping the path-exit search/override/merge. Make the path-exit pathway bypass the freeze while ATR/SL/TP/maxHold stay frozen.

#### Files & changes

**1. Un-link randomize from freeze**
- `lib/finder/finder-manager-logic.ts:207-210`: change to
  ```ts
  freezeRiskManagement: input.freezeRiskManagement || input.polymarketScoringEnabled,
  randomizePathExitParams: !input.polymarketScoringEnabled
      && input.randomizePathExitParams === true,
  ```
  (drop the `&& !input.freezeRiskManagement`). Polymarket still forces off.

**2. Un-skip path-exit search params when freeze + randomize**
- `lib/finder/finder-runner-core.ts` `buildFinderSearchBaseParams` (L348-350): when frozen, currently returns early with just strategy defaults. Add before the early return:
  ```ts
  if (shouldRandomizePathExitParams(settings, options)) {
      addPathExitSearchParams(baseParams, settings);
  }
  ```
  So path-exit params join the search space even when frozen; ATR/SL/TP/maxHold stay frozen.

**3. Un-skip path-exit overrides when freeze + randomize**
- `resolveFinderRiskOverrides` (L448-453): when frozen, currently returns `settings`/`rustSettings` unchanged. Before returning, if `shouldRandomizePathExitParams`, call `applyPathExitOverrides(settings, params, backtestOverrides, options)` against a fresh `backtestOverrides` and apply to the backtest (not rust — path exits force TS anyway) side. Mirror the existing non-frozen call pattern.

**4. Un-skip path-exit merge in Apply when freeze + randomize**
- `mergeFinderRiskParamsIntoBacktestSettings` (L514-516): when frozen, currently returns `merged` unchanged. Before returning, if `shouldRandomizePathExitParams(settings, options)`, run the existing `PATH_EXIT_PARAM_SPECS` merge loop (the same code at L547-558) on `merged`. So Apply writes path-exit params; ATR/SL/TP/maxHold stay frozen.

**5. UI hint update**
- `html-partials/tab-finder.html:215`: update the Randomize Path Exits hint to make the freeze interaction explicit:
  "When Path-Dependent Exits are enabled, Finder varies the numeric controls for the selected path-exit mode and applies them with the result. Works even when risk settings are frozen — only path-exit controls are varied; other risk settings stay fixed."

### Risk notes
- Cooldown change touches the engine hot loop but is a single-int gate per entry attempt (cheap).
- All 4 engine loop paths must be updated consistently — this is the main complexity.
- Renaming `signalExitReentryCooldownUntilBarIndex` → `entryCooldownUntilBarIndex` is cosmetic; could leave the name to minimize churn. **Decision: leave name unchanged to keep the diff surgical** (only the arming logic and the gate conditions change). The variable already generalizes naturally.
- Feature 2 is pure logic-branch surgery in 4 functions + 1 line in manager-logic; small surface, well-bounded by existing tests.
