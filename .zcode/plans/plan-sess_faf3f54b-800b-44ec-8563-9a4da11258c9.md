# Batch Audit Findings — Implementation Plan

Branch: `fix/batch-audit-findings` (worktree at `Strategies-Finder-batch-audit`).

The eight findings are independent and additive. Each is implemented minimally, with a regression test that locks the intent (AGENTS.md rule 8). No behavioral or naming changes outside what each finding requires.

## Finding 1 — Make Batch Run single-flight

**Browser (`batch-backtest-service.ts`)**
- Add `private runInFlight = false;` to `BatchBacktestService`.
- At the TOP of `runBatch()` (before symbol validation, before any await): if `this.runInFlight` is true, set status text `"Batch is already running…"` and `return`. Otherwise set `this.runInFlight = true`.
- In the existing `finally` of `runBatch` (the one that gates on `token === this.runToken`), set `this.runInFlight = false;`.

This closes the double-click window: the button is disabled later (line 354) but a double-click stacks two `runBatch()` invocations on the event loop before either disables the button.

**Server (`batch-backtest-vite-plugin.ts` `handleRunRequest`)**
- Already does the right thing in spirit, but `resolveStrategy(strategyKey)` (an async `loadBuiltInStrategyByKey`) currently runs AFTER the `runOwner !== RUN_OWNER_NONE` check at line 1371. Two requests can both pass that check, then both call `resolveStrategy`, then both try to claim.
- Move the ownership claim to BEFORE `resolveStrategy`: take `const owner = ++runOwnerGen; runOwner = owner;` immediately after the existing `runOwner/minerOwner` 409 checks, and add a `try/finally` that releases ownership on any early throw (400 validation errors, resolveStrategy failures). The current late-claim block (lines 1413–1414) is removed. The `pendingStopRunId` consume check (line 1419) stays immediately after the claim.

**Test**: add to `tests/batch-backtest-service-lifecycle.browser.spec.ts` — a rapid double-click on `batchBacktestRunBtn` produces exactly one `/api/batch-backtest/run` POST. Add to `tests/batch-backtest-server-plugin.spec.ts` — two concurrent `handleRunRequest` calls (one queued via Promise.all while the other holds ownership) → the second gets HTTP 409.

Throw/guard on runId mismatch (returns `[]` and signals the caller).

  2. The terminal-reattach branch of `reattachToInProgressServerRun` — currently ignores `payload.lastRun.rows` entirely (line 1273 et al). Add a paginated drain via `reconcileStatusRows` so a reloaded tab recovers terminal rows, mirroring the recovery path.
  3. The in-progress reattach paged-drain (lines 1386–1404).
- The terminal reattach path also needs to drain `nextOffset` pages (today it does not) — the shared helper handles this.

**Test**: add to `tests/batch-backtest-service-lifecycle.browser.spec.ts` —
(a) stream prefix of N rows then a recovery status response that includes those N rows → exactly N rows in DOM (no duplicates);
(b) reload after server completion where `lastRun.rows` is paginated → all rows restored.

## Finding 3 — Bound the Mine artifact parse cache

**`batch-backtest-vite-plugin.ts` `ArtifactStore`**
- Replace `readonly parsedCache = new Map<…>()` with a bounded LRU. Add `const PARSED_ARTIFACT_CACHE_MAX = 32;` (module-level, near other caps).
- In `loadStored(meta)`: on hit, `delete` + `set` to refresh recency; on miss, after `set`, if `size > PARSED_ARTIFACT_CACHE_MAX`, evict the oldest entry (`this.parsedCache.keys().next().value` → `delete`). Map iteration order is insertion order, so the oldest is the LRU victim.
- Add private counters: `parsedCacheHits`, `parsedCacheMisses`, `parsedCacheEvictions`, `parsedCachePeak`. Reset on `detach()` (set to 0).
- Expose them on the store as a method `parsedCacheStats()` and include them in the existing benchmark `minerProfile`-style surface (Finding 4's `artifactStats` is a separate concern; cache stats are diagnostics-only).
- Plug them into the `batch.server.run.complete` debug event and (where available) the Stability `minerProfile`-equivalent place.

**Test**: add to `tests/batch-backtest-server-plugin.spec.ts` — populate 40 artifacts, request 40 `loadStored`, assert `parsedCache.size <= 32`, evictions>0, hits-then-misses behavior on re-reads.

## Finding 4 — Surface partial artifact-write failures

**`batch-backtest-vite-plugin.ts` `ArtifactStore`**
- Add counters `artifactStats = { eligible: 0, stored: 0, failed: 0, bytesWritten: 0 }`:
  - `eligible` incremented at the top of `store()` (after the synthetic-pair gate passes).
  - `stored` and `bytesWritten` incremented in the write IIFE on success (`data.byteLength`).
  - `failed` incremented in the catch.
- Reset on `detach()`.
- Expose via `store.artifactStats()`.
- In `processRunBatch`'s `done` event path (where `serverHasArtifacts` is computed), pull stats off the captured `store` and include them in the `done` event payload (`BatchStreamEvent` `done` type) and in `BatchRunSnapshot` (so `/status.lastRun` carries them).
- Browser: extend the `done` handler to format `Batch complete — artifacts X/Y; Mine will omit Z failed writes.` into the status text when `failed > 0`. Keep the Mine button enabled as long as `stored > 0`.

**Stream types (`batch-backtest-stream-types.ts`)**
- Add optional `artifactStats?: { eligible: number; stored: number; failed: number; bytesWritten: number }` to the `done` event. (Optional, backward-compatible.)

**Snapshot type (`batch-backtest-snapshot.ts`)** — no change required for v1; the run summary is in the `done` event text. (Keep scope minimal per AGENTS.md rule 2.)

**Test**: add to `tests/batch-backtest-server-plugin.spec.ts` — inject an `ArtifactStore` whose `writeArtifactFile` throws on every other write → `done.artifactStats.failed > 0`, `done.artifactStats.stored > 0`, summary status text mentions the failure count.

## Finding 5 — Distinguish completed/failed/cancelled/skipped rows in benchmark

**`batch-backtest-runner.ts`**
- Add a new status `"skipped"` to `BatchBacktestSymbolStatus`. Replace the cancelled-tail backfill (line 327–337) so the synthetic row uses `status: "skipped"` instead of `"no_trades"` (still keeps `error: "Skipped (cancelled)."`).

**`batch-backtest-service.ts` `recordRunBenchmark`**
- Compute `attempted = lastResults.length`, `completed = rows where status is profitable/losing/flat/no_trades (a row that ran)`, `failed = load_failed + run_failed`, `cancelled = number of rows with status==="skipped"`, and `skipped = cancelled` (same thing, named explicitly for the benchmark).
- Only call `recordRunBenchmark` when the run reached a known terminal state: skip it when the run was cancelled mid-flight AND no terminal `done`/`recovered` was reached (currently `recordRunBenchmark` runs unconditionally in `finally`). Add `outcome: "done" | "cancelled" | "fatal" | "incomplete"` derived from the existing terminal flags.
- New fields added to `BatchBenchmarkRunPhase`: `attempted`, `completed`, `cancelled`, `skipped`, `outcome`. Keep existing `loaded`/`failed` for backward-compat.
- Bump `BATCH_BENCHMARK_SCHEMA` from `"batch.benchmark.v1"` to `"batch.benchmark.v2"`.

**Test**: add to `tests/batch-benchmark-snapshot.spec.ts` — verify the schema bump and the new fields; add to `tests/batch-backtest-runner.spec.ts` — cancelled-tail rows report `status: "skipped"`.

## Finding 6 — Scope every status page to runId

**Server (`handleStatusRequest` and the `/status` route)**
- Change signature to `handleStatusRequest(afterRow, limitRaw, requestedRunId?: string)`.
- If `requestedRunId` is provided AND it does not match `runState?.runId`, return `{ ok: true, runMismatch: true, run: null, lastRun: null, miner: null }` (HTTP 200, explicit mismatch field — keeps the contract read-only and recoverable; 409 would force the browser into error handling).
- Parse `?runId=` from the URL in the route handler and pass it through.

**Browser (`batch-backtest-service.ts`)**
- Every `/api/batch-backtest/status` fetch adds `&runId=${this.activeServerRunId}` when set (initial recovery, paged drains in recover + reattach, refreshServerArtifactState stays unscoped because it intentionally probes the latest server state — keep that one unscoped, document why).
- On `runMismatch`, the recovery loop stops fetching more pages and treats the run as not-adoptable (existing behavior for a fingerprint mismatch).

**Test**: add to `tests/batch-backtest-server-plugin.spec.ts` — a completed run carries `runId="A"`; `handleStatusRequest(0, undefined, "B")` returns `runMismatch: true` with `lastRun: null`.

## Finding 7 — Centralize typed Batch NDJSON POST helper

**New leaf module: `lib/batch-backtest/batch-ndjson-post.ts`**
- `postBatchNdjson<TEvent extends { type: string }>(opts: { endpoint, body, handlers, signal? }): Promise<void>` doing: `fetch`, response/body validation, JSON error extraction (shared `extractServerErrorMessage`), and `consumeNdjsonStream(..., { requireTerminal: true })` against the typed `TEvent` union, dispatching to the provided handlers.
- Handlers are an object literal keyed by event type (camelCase, e.g. `onStart`, `onDone`, `onFatal`) so each call site retains its typed surface.

**`batch-backtest-service.ts`**
- Refactor the five POST sites (run / mine / stability / portfolio-fit / mine-prediction) to use `postBatchNdjson`. Preserve endpoint-specific typed handler objects. Do NOT move lifecycle/UI state into the helper (each call site keeps its pre-/post-await UI mutations).
- The helper covers transport only; UI state (`beginAnalysisBusy`, button toggles) stays at call sites.

This is the highest-effort refactor. Per AGENTS.md rule 2, only do it if the four transport mechanics are genuinely duplicated. They are — confirmed at the five call sites.

**Test**: add a focused unit test for the helper (success path, non-2xx path, truncated stream → throws via `requireTerminal`). Re-run the existing five browser-side lifecycle tests to confirm parity.
