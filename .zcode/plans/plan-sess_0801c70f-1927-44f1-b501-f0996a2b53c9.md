## Goal

An A/B test that measures whether filtering batch trades through Mine's LONG verdict improves actual P&L. Control = all trades (current behavior). Treatment = only trades where Mine said LONG at the entry bar. Compare net P&L, trade count, win rate, profit factor.

## Design (per the audit's recommendation, Option A1)

The test runs per-pair, on the server, reusing the batch artifacts (same as Mine Prediction):

1. **Control arm:** the existing batch result per pair (already computed during the Run). No re-execution needed — use the stored `result.trades` and `result.netProfit`.

2. **Mine verdict lookup:** for each pair's entry trades, find the entry bar's timestamp on the base asset's OHLCV, slice to `[:N+1]`, run Mine's engine, check if `verdict.verdict === "LONG"`. Reuse the prepared pairs from the artifact store (same as Mine Prediction does).

3. **Treatment arm:** filter the pair's signals — drop `type: "buy"` entries whose entry bar doesn't have Mine LONG. Keep all sell/exit signals. Re-run via `executeBacktestFromSignals(data, interval, filteredSignals, settings, capital, ctx)` to get a fresh `BacktestResult` that reflects the filtered trade list through the real exit overlay.

4. **Report:** aggregate control vs treatment across all pairs:
   - Total net P&L (control vs treatment)
   - Trade count (control vs treatment)
   - Win rate, profit factor, avg trade, max DD
   - Per-pair delta (which pairs improved, which worsened)
   - Verdict: TREATMENT_BETTER / CONTROL_BETTER / NO_DIFFERENCE

## Architecture

Mirrors the Mine Prediction endpoint pattern:
- **Server-side compute** in `lib/batch-backtest/batch-mine-prediction-ab-engine.ts` (pure leaf, no lightweight-charts)
- **Endpoint** `POST /api/batch-backtest/mine-prediction-ab` (read-only on artifacts, streams progress per-pair)
- **UI:** a new button "Mine A/B Test" next to Mine Prediction, reusing the same config row (From/To/Dir/Samples/Step/Horizons don't apply — the A/B test runs on the actual batch trades, not sampled historical bars)
- **Report:** multi-line panel, same `batch-miner-status--multiline` pattern

## Key decisions

- **Base-asset verdict only:** a pair trade is "Mine-LONG-gated" if Mine's verdict for the BASE asset at the entry bar is LONG. (Quote-asset gating is a future option; base-only is simpler and matches how Mine's breadth snapshots are constructed.)
- **No sampling:** the A/B test runs on ALL the batch's actual trades, not sampled bars. This is the real P&L test, not a statistical proxy.
- **`executeBacktestFromSignals`** for the treatment arm: re-runs the filtered signal list through the real backtest engine with the user's real exit overlay. This captures position-sequencing effects that post-hoc trade-subsetting cannot.
- **No auto-horizons:** the treatment arm uses the batch's existing settings (horizons come from the pair trades themselves, not from Mine's auto-horizon derivation).

## Report format

```
MINE_AB   | strategy=<key> interval=<int> pairs=<P> direction=long
MINE_AB   | NOTE: Control = all batch trades. Treatment = only trades where Mine said LONG at the entry bar. P&L through the real exit overlay.
SUMMARY  | Control: trades=<N> netPnl=$<X> winRate=<%> pf=<X> avgTrade=$<X> maxDD=$<X>
         | Treatment: trades=<N> netPnl=$<X> winRate=<%> pf=<X> avgTrade=$<X> maxDD=$<X>
DELTA    | PnL: +$<X> (+<%>) | Trades: −<N> (−<%>) | WinRate: +<pp> | PF: +<X>
VERDICT  | TREATMENT_BETTER (+$<X> net, +<pp> win rate) | CONTROL_BETTER | NO_DIFFERENCE
CAVEAT   | <e.g. "Treatment took 30% fewer trades for 5% more PnL — Mine is cutting losers">
```
